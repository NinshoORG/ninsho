              The differences at a glance

              JWTNinsho
              Where your login livesA token in localStorage, readable by any scriptAccess token in memory, refresh token in an HttpOnly cookie, a key that cannot be exported
              Signing outThe browser forgets its copy. Other copies keep working until they expireThe server ends the session. Every copy stops working at once
              A stolen tokenWorks from anywhere until it expiresUseless without this browser’s key
              Sign out everywhereNot possible, short of signing out every userOne call ends every session for the account
              See signed-in devicesNo. The server keeps no listYes
              Work per requestA signature check. No lookupOne Redis read and a signature check
              What the server storesNothingSessions in Redis, each expiring on its own

              What neither one fixes: a malicious script running on this page can act as you while the page is open. Ninsho stops it from taking your login away and using it elsewhere. Preventing that script is still the site’s job.

              Accounts: Postgres. Ninsho sessions: Redis. The JWT side uses HS256 with a 15-minute expiry. Nothing here is sent anywhere but this server.
