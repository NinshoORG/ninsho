Two tabs, one sign-out

Ninsho + device key only
  1. Sign in on the Shop tab with Ninsho + device key.
  2. Open a second tab and sign in there too.
  3. Sign out in the tab where you signed in last.
  4. The other tab switches to “Not signed in”. No token is passed between tabs.

Signing in on one tab replaces the login in the others, so the most recent tab is the one holding the live session.

Walkthrough in 8 steps

About 10 minutes

Open your browser’s developer tools (F12) alongside. Every claim below can be checked there.

  1. Sign in with Plain JWT

    Choose Plain JWT at the top, click Alice, then Sign in.

  2. See where the token is kept

    DevTools → Application → Local Storage. The token is under secureshop_jwt_token, readable by any script on the page.

  3. See it being sent

    DevTools → Network. Click Reload my orders. The request carries Authorization: Bearer ….

  4. Experiment A: a copied JWT after sign-out

    Copy the token, sign out, replay it. The server answers 200: signing out did not stop the copy.

  5. Experiment B: ending a session on two servers

    Both servers answer 200. End the session on A. Replays on A and B both get 401.

  6. Sign in with Ninsho + device key and look again

    Local Storage is empty. IndexedDB holds secureshop-dpop-keys, a key that cannot be exported. The refresh cookie is HttpOnly. In Network, each request has Authorization: DPoP … and a fresh DPoP header.

  7. Experiment C: a stolen token without the key

    Token alone: 401. Signed with another key: 401. The same valid proof twice: 200, then 401.

  8. Two tabs

    Sign in on two tabs, then sign out in the one you signed in on last. The other tab is signed out too.
