Ninsho protocol explorer

Every button below runs the real library — not a mock, not a re-implementation. What you get back is the actual bytes on the wire, the actual keys written to the store, and the actual audit events. Where a claim is made, the evidence for it is on the screen next to it.

1 · A session, end to end

Creating a session mints two credentials: a short-lived access token for requests, and a refresh token that rotates. Watch what reaches the store.

2 · Attacks, and what stops them

The interesting part of an auth library is not that the happy path works. It is what happens when someone attacks it. Each of these is a real attempt against the running system.

Replay a rotated refresh token

A thief steals a refresh token, the legitimate client rotates it, and the thief presents the old one. Refresh at least once first, then run this.

Tamper with an access token

Flip a single character and present it.

Use a password-reset link twice

A forwarded email, or a corporate mail scanner that pre-fetches links.

Race two reset requests

Asking for a second reset email must invalidate the first — including when both requests arrive at the same instant. This one found a real bug.

3 · Your browser holds the key

Everything above ran on the server. This section does not: the private key is generated in this page, marked non-extractable, and never leaves it. What reaches the server is a signature. It runs @ninsho/client — the same bundle an application would install, served straight from the package.

4 · Anatomy — the actual bytes

Each of these generates a genuine artefact with the shipped code, then annotates it byte by byte: where each field sits, how wide it is, and why it is there. Nothing below is a hand-written sample — a decoder shown bytes the library never produced would teach the wrong thing.

5 · What is actually in the store

The live keyspace. Paste any token this page has shown you into the box and search for it — the claim is that you will not find it, because only SHA-256(token) is ever written.

6 · The audit trail

Structured security events. The shape is deliberately narrow — there is no free-form payload that could accidentally carry a token, a password, or a request body.
