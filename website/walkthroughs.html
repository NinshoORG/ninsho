How it works

Seven attacks, recorded from the real library.

Every request, status code, store operation and audit event below came from the published library answering real HTTP requests. Each step says what should happen before it runs, and the recording is refused if the library disagrees. CI records all of it again on every push, and fails if the library stops behaving the way this page shows.

    The app

    The whole program behind every frame.

    Each walkthrough starts this app on a real socket, backed by a real in-memory store, and sends it real requests. It is short on purpose: a visitor should be able to read every line that produced what they just watched.

    It takes two liberties, both marked at the top of the file — tokens come back in the JSON body so they can be shown, and passwords are compared against a two-user table. examples/express-api does both properly.

    Why a recording can be believed
    
      
    A recording is exactly the thing that drifts. So these are checked.
    
      
    
        This project began as an audit of a library whose attack suite tested a reimplementation of
        its middleware instead of the middleware it shipped. A demo page that replays old recordings
        is the same failure waiting to happen, so three things keep these honest.
      
    
      
    
        
    
          01 — REAL
          
    Nothing is typed in
    
          
    A real socket, real HTTP, the published package. Store operations are logged by a pass-through wrapper around a real store — never a mock.
    
          
    Recorder · examples/playground/src/walkthroughs.ts
    
        
    
        
    
          02 — ASSERTED
          
    Each step commits first
    
          
    A step declares its status and the audit events it expects before it runs. If the library does anything else, nothing is written. A page cannot say “refused” over a 200.
    
          
    Asserted per step · Harness.step()
    
        
    
        
    
          03 — RE-RECORDED
          
    CI checks it on every push
    
          
    Recorded again against each commit's build and compared — statuses, store operations, events. Every cited test must still exist, and the app source above must be the source that ran.
    
          
    CI job · Website walkthroughs match the library
