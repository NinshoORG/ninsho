What it stops

Six attacks, and the test that proves each one fails.

Every card below runs in the demonstration app. You click the attack and watch it lose, with the store operations printed underneath — and the file that pins it is named right here.

Stolen refresh token

Token theft, replayed

An attacker redeems a rotated refresh token before the real client does. Most libraries return a 401 and move on, leaving the attacker holding a valid chain.

Entire family revoked, alarm raised · session.test.ts

XSS exfiltration

Access token copied out

Script injected into your page reads the token and sends it elsewhere. A bearer token is just a string, so it works anywhere, forever.

Inert without the non-extractable key · dpop-integration.test.ts

Botnet credential stuffing

One account, thousands of hosts

Attempts spread so thin that no single address approaches a per-IP limit — which is precisely what a per-IP limit alone never sees.

Caught by the per-account bucket · ratelimit.test.ts

Forwarded reset link

Password reset, used twice

A reset email is forwarded, or two tabs race the same link. Read-then-delete lets both through.

Atomic single use — exactly one wins · ott-race-probe.test.ts

Object-level access

Reading someone else's orders

A signed-in user changes an ID in the URL. Authentication passed, so most middleware waves it through — the top of the OWASP API list.

Ownership checked; undeterminable is refused · middleware.test.ts

Store outage

Redis goes down mid-attack

Revocation cannot be checked. A library that keeps serving is accepting tokens it has no way to know were revoked.

Fails closed — 503, against a dead Redis · store-invariants.test.ts

The rule

A security property must name the test that demonstrates it — or it does not ship.

Ninsho is a ground-up rebuild of an earlier library, started after an audit found that its release could not be built from a clean checkout, bundled a test double into its production artifact, and disabled its own headline feature during a store outage — while advertising instant revocation and “all attacks blocked”.

The claims were not dishonest by intent. They outran the evidence, which for an authentication library amounts to the same thing.

So every claim here carries its citation, and that rule has teeth: writing this site's own performance page caught two documents in this repository quoting different multiples for the same comparison, and a published benchmark timing a verification with two of its checks silently disabled.

Enforced in review · CONTRIBUTING.md, PULL_REQUEST_TEMPLATE.md

What is built

Complete, not a roadmap.

Anything not listed here does not exist. That is the point of listing it.

Two token strategies

Opaque by default — no signing keys at all. PASETO v4.public when services must verify independently.

opaque · paseto

Proof-of-possession

Tokens bound to a non-extractable browser key, with a fresh signed proof on every request.

RFC 9449 · DPoP

Passkeys, complete

All seven attestation formats WebAuthn L3 defines — and what each one cannot prove is stated as plainly as what it can.

packed · apple · tpm · fido-u2f · android-key · safetynet · none

Authorization guards

Roles, scopes, ownership, tenancy and step-up. Exact matching, never prefix or wildcard.

requireRole · requireOwner · requireFreshAuth

Rate limiting, two-dimensional

Per-address and per-account together, because either one alone fails in the opposite direction.

sliding window · trustProxy required

Four frameworks

Express, Fastify, Hono and Koa. Each tested against the real thing; none imported.

/fastify · /hono · /koa

Get started

Running in about a minute.

Not on npm yet, so today you build from source. Everything below runs the real library, not a preview of one.

01 — CLONE AND VERIFY

Nothing here asks to be believed

$ git clone https://github.com/NinshoORG/ninsho.git
$ cd ninsho

$ npm ci
$ npm run build
$ npm run test

→ 2,056 passing
02 — OPEN THE DEMONSTRATION

Ten panels. Run the attacks yourself

$ npm run dev --workspace @ninshorg/playground

→ http://localhost:4000

# or, in a container
$ docker build -f examples/playground/Dockerfile \
    -t ninsho-playground .
$ docker run -p 4000:4000 ninsho-playground
03 — WIRE IT UP

One store, then mount the guards

const auth = new Ninsho({
  store: new RedisStore(url)
});

app.post('/account/email',
  auth.verify(),
  auth.requireFreshAuth(300),
  handler);

// Refreshing is not re-authenticating.
