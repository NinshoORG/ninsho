LINKEDIN

I shipped an auth library, then audited it. The release couldn't be built from
a clean checkout, a test double was in the production bundle, and it defaulted
to admitting requests when the datastore went down. None of the claims in its
README were dishonest — they'd just outrun the evidence, which for an auth
library is the same failure.

So I rebuilt it under one rule: a security claim must name the test that
demonstrates it, or it doesn't get made.

Ninsho — sessions, passkeys, refresh rotation with theft detection, DPoP
proof-of-possession, and all seven WebAuthn attestation formats. 2,056 tests
against real Redis. Every claim in the docs links to the file that proves it.

npm i @ninshorg/server · github.com/NinshoORG/ninsho
